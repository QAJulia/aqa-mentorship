# WEEK 5 – Locators Notes

## 1. Overview
Locators tell Selenium which element on the page to interact with. Good locators are **stable**, readable, and as specific as needed but no more.

## 2. id

**How it works**

- Matches element with attribute `id="value"`.
- Selenium: `driver.findElement(By.id("login-button"));`

**Advantages**

- Usually unique on the page.
- Fast and reliable when controlled by developers.

**Disadvantages**

- Not always present.
- Can change when frontend is refactored.

## 3. name

**How it works**

- Matches element with attribute `name="value"`.
- Selenium: `driver.findElement(By.name("email"));`

**Advantages**

- Common on forms.
- Sometimes more stable than `id` when ids are autogenerated.

**Disadvantages**

- Not guaranteed to be unique.
- Some modern UIs do not use `name` attributes consistently.

## 4. className

**How it works**

- Matches element by CSS class attribute.
- Selenium: `driver.findElement(By.className("btn-primary"));`

**Advantages**

- Easy to use when there is a distinctive class.
- Useful for groups of similar elements (lists, buttons).

**Disadvantages**

- Often non-unique (same class on many elements).
- Frontend frameworks generate long multi-class values.

## 5. cssSelector

**How it works**

- Uses CSS selector syntax (tag, id, class, attributes, hierarchy).
- Selenium: `driver.findElement(By.cssSelector("button#login.btn-primary"));`

**Advantages**

- Very flexible, supports complex combinations.
- No dependency on browser-specific tools.
- Usually faster or equal to XPath.

**Disadvantages**

- Syntax can be hard for beginners.
- Does not support all DOM traversal directions (no parent axis).

## 6. XPath (overview)

**How it works**

- Path-like syntax to navigate XML/HTML document tree.
- Selenium: `driver.findElement(By.xpath("//button[@id='login-button']"));`

**Advantages**

- Very powerful: supports complex conditions, axes, functions.
- Can traverse both down and up the DOM tree.

**Disadvantages**

- Easy to overcomplicate, which makes tests brittle.
- Absolute XPaths break easily on layout changes.

## 7. Absolute vs Relative XPath

### Absolute XPath

- Starts from the root `html` node and follows the full path.
- Example: `/html/body/div[1]/div[2]/form/input[1]`

**Pros**

- Quick to generate with browser tools.

**Cons**

- Very fragile on any page structure change.
- Hard to read and maintain.

### Relative XPath

- Starts from anywhere in the document using `//` or from a specific node.
- Example: `//form[@id='loginForm']//input[@name='email']`

**Pros**

- Much more stable and readable.
- Can focus on semantic attributes (id, name, text).

**Cons**

- Can still be brittle if tied to unstable attributes or deep hierarchies.

## 8. XPath axes (with examples)

Axes define the direction of navigation from a current node. https://www.w3schools.com/xml/xpath_axes.asp

Common axes:

- `child::` – direct children of the current node.  
  Example: `//ul[@id='menu']/child::li` – all `li` directly under the menu list.
- `descendant::` – all descendants (children, grandchildren, etc.).  
  Example: `//div[@id='content']/descendant::a` – all links inside the content area.
- `parent::` – the parent of the current node.  
  Example: `//span[@class='error-message']/parent::div` – the wrapper `div` for an error message span.
- `ancestor::` – all ancestors (parent, grandparent, etc.).  
  Example: `//input[@id='search']/ancestor::form` – a `form` containing the search input.
- `following-sibling::` – siblings after the current node at the same level.  
  Example: `//label[@for='email']/following-sibling::input[1]` – the first `input` after the email label.
- `preceding-sibling::` – siblings before the current node at the same level.  
  Example: `//input[@id='email']/preceding-sibling::label[1]` – the label before the email input.
- `following::` – all nodes after the current node in the document.  
  Example: `//h2[text()='Features']/following::ul[1]` – the first list after a "Features" header.
- `preceding::` – all nodes before the current node in the document.

### Mini-example (login form)

Suppose we have a login form like on `https://the-internet.herokuapp.com/login`.

- Username input by id:  
  `//input[@id='username']`
- Password input as following-sibling of label:  
  `//label[@for='password']/following-sibling::input`
- Login button by descendant:  
  `//form[@id='login']/descendant::button[@type='submit']`

## 9. XPath Functions

XPath provides built-in functions for working with strings, making it powerful for handling dynamic elements and partial matches.

**Official XPath Documentation:** https://www.w3.org/TR/xpath/

### contains()

The `contains()` function checks if a string contains a specific substring. Very useful for dynamic attributes or partial text matching.

**Syntax**
```
contains(string, substring)
```

**Common use cases**

- **Attribute contains a value:**  
  `//button[contains(@class, 'btn-primary')]` – matches button with class containing "btn-primary"
  
- **Text contains a value:**  
  `//div[contains(text(), 'Welcome')]` – matches div containing text "Welcome"
  
- **Dynamic IDs:**  
  `//input[contains(@id, 'email')]` – useful when ID has dynamic prefix/suffix like `user-email-12345`

**Example with AND operator:**  
`//div[@class='container' and contains(@id, 'main')]` – div with class "container" AND id containing "main"

**Important notes**
- `contains()` performs substring matching, not exact matching
- Case-sensitive by default
- When passing a node-set as first argument, only the first node is evaluated

### starts-with()

The `starts-with()` function checks if a string begins with a specific substring. Ideal for dynamic attributes with stable prefixes.

**Syntax**
```
starts-with(string, substring)
```

**Common use cases**

- **Attribute starts with a value:**  
  `//input[starts-with(@id, 'user-')]` – matches inputs with IDs like `user-email`, `user-password`
  
- **Text starts with a value:**  
  `//h2[starts-with(text(), 'Chapter')]` – matches headings like "Chapter 1", "Chapter 2"
  
- **Dynamic IDs with known prefix:**  
  `//div[starts-with(@id, 'message-')]` – useful when ID format is `message-12345`, `message-67890`

**Example combining multiple conditions:**  
`//button[starts-with(@id, 'submit-') and contains(@class, 'btn')]` – button with ID starting with "submit-" AND class containing "btn"

**Important notes**
- Case-sensitive
- Returns `false` if the attribute is `NULL` or empty
- More specific than `contains()` – better for predictable prefixes

### text()

The `text()` function selects the text content of a node.

**Examples**

- **Exact text match:**  
  `//button[text()='Login']` – button with exact text "Login"
  
- **Text with contains:**  
  `//p[contains(text(), 'error')]` – paragraph containing the word "error"
  
- **Text with starts-with:**  
  `//h3[starts-with(text(), 'Step')]` – heading starting with "Step"

### normalize-space()

The `normalize-space()` function removes leading/trailing whitespace and collapses multiple spaces into one. Very useful for handling inconsistent spacing in HTML.

**Syntax**
```
normalize-space(string)
```

**Example**

- **Handling extra whitespace:**  
  `//button[normalize-space(text())='Login']` – matches button even if text has extra spaces
  
- **Combined with contains:**  
  `//div[contains(normalize-space(text()), 'Welcome')]` – matches text with any whitespace variations

### Combining Functions

You can combine multiple XPath functions for powerful queries:

```xpath
// Find button with class starting with 'btn-' and text containing 'Submit'
//button[starts-with(@class, 'btn-') and contains(text(), 'Submit')]

// Find input with ID starting with 'user' and name containing 'email'
//input[starts-with(@id, 'user') and contains(@name, 'email')]

// Find div with normalized text exactly matching 'Welcome'
//div[normalize-space(text())='Welcome']

// Find link following a header that contains 'Documentation'
//h2[contains(text(), 'Documentation')]/following-sibling::a[1]
```

### Additional String Functions

- **substring(string, start, length)** – extracts part of a string  
  Example: `//div[substring(@id, 1, 4)='user']` – div with ID starting with "user"
  
- **string-length(string)** – returns the length of a string  
  Example: `//input[string-length(@value) > 10]` – input with value longer than 10 characters
  
- **concat(string1, string2, ...)** – concatenates strings  
  Example: `//div[@id=concat('user-', '123')]` – div with ID "user-123"

### Practical Example (Dynamic Elements)

Suppose you have a page with dynamically generated IDs:

```html
<button id="submit-btn-12345" class="btn btn-primary">Submit</button>
<input id="user-email-67890" name="email" />
<div class="error-msg-active">  Invalid email  </div>
```

**XPath strategies:**

```xpath
// Button with dynamic ID but known prefix
//button[starts-with(@id, 'submit-btn-')]

// Input with dynamic ID containing 'email'
//input[contains(@id, 'email')]

// Div with class containing 'error' and normalized text
//div[contains(@class, 'error') and normalize-space(text())='Invalid email']

// Button with class containing 'btn' AND 'primary'
//button[contains(@class, 'btn') and contains(@class, 'primary')]
```

## 10. Finding XPath in DevTools (Chrome)

- Open the page.
- Right-click the element, choose **Inspect**.
- In **Elements** tab, right-click the highlighted node.
- Choose **Copy → Copy XPath** (gives an absolute XPath – good as a starting point only).
- Instead of using it directly, simplify the XPath manually to a more stable relative one.
- You can test XPath and CSS in DevTools:
    - Press `Ctrl+F` (`Cmd+F` on macOS) in Elements tab.
    - Type your XPath or CSS selector.
    - DevTools shows the number of matched nodes and highlights them.

## 11. Strategy for choosing locators

Recommended order in real projects:

1. `id` (if stable and meaningful).
2. `name` (on forms where unique).
3. `cssSelector` using stable attributes (`data-test`, `aria-label`, `role`).
4. `xpath` as a powerful fallback (prefer relative with semantic attributes, functions, and axes).

**When to use XPath functions:**

- **Dynamic elements:** Use `contains()` or `starts-with()` for IDs/classes that change
- **Partial matching:** Use `contains()` when you know only part of the attribute
- **Whitespace issues:** Use `normalize-space()` for text with inconsistent spacing
- **Predictable prefixes:** Use `starts-with()` when the beginning of attribute is stable

**Avoid**

- Overly long absolute XPaths.
- Locators based only on index (e.g., `div[4]/span[2]`) unless there is no better option.
- Overusing `contains()` when exact match is possible (it's slower).
- Using functions on large node-sets (can impact performance).
